# 美术资产与角色皮肤制作流程

这份流程来自已完成的桌面皮肤制作，目标是同一角色的完整形象、可读终端背景与可交互软绒UI。图像生成是独立制作步骤；仓库脚本不调用imagegen、网络或TTS，也不把插值放大称为模型超分。

## 1. 先锁定身份，再确定画风

为每位角色记录当前官方角色页、清晰立绘、CV来源、研究日期、角色ID与显示名。将官方当前版本和早期测试/同人/社区图分开。只把核实的设定写入人设；看不清的饰物和衣装不能靠猜。

有用户明确修正时，把修正作为本次制作要求记录。例如庄方宜的青绿虹膜、金绿内层与红粉眼线必须分开：红色眼妆不能误写为红虹膜。原始参考图保留字节、网址和SHA256；最终清单只选择已通过修正的版本，不递归复制生成目录。

[图像提示词模板](../templates/image-prompts.json)把必填身份、配色、眼色和画风分离。已有成品可用作画风参考，保持其头身比例、阴影方式和玩偶材质；不把参考人物的发饰或服装迁入新角色。没有取得图片授权时，仓库只记录画风描述与来源，不重新授权参考图。

## 2. 三种资产，两个切换外观

| 资产 | 视觉目的 | 必须保留 | 人工验收 |
|---|---|---|---|
| doll | 圆头坐姿软布娃娃、短圆脚，触碰及捏捏 | 角色发型/角/耳、衣装关键关系、正确眼色 | 像旧版已认可的软玩偶，不做成写实长身材或另一人物 |
| chibi | 精致日系半身Q版 | 完整头发/头饰、可辨衣装与眼睛 | 细节清楚，头像小尺寸仍能辨认 |
| bot | 简洁倾斜圆脸、胶囊圆眼、平涂软阴影 | 发型轮廓、眼色、配色与衣装 | 沿用已认可的简Bot风格，不退回高细节动漫脸 |

chibi/bot构成两个可切换角色外观，doll是独立挂件。运行时默认外观、大小和位置属于用户设置；变更图片时不重置这些设置，不替换其他人物的资产。

交付8-bit真实RGBA PNG，不能把白/黑/绿背景或画上去的棋盘格当透明。新生成sprite上方至少16px透明留白，四角alpha=0，双角、发髻、羽饰、最外围发丝完整。旧角色若要求保持字节不变，记录其既有留白警示，不为统一阈值擅自修图。半身图允许衣摆在下边缘构图裁切，但头发和头饰不可被截断。

用统一比例缩小到26/40/64/96px检查头像，不拉伸脸以填满画布。[验证器](../scripts/Validate-Assets.py)检查真实RGBA、尺寸、透明边距和批准哈希；眼色、服装、风格与画上去的假透明仍须人工看图。

## 3. 母图与独立环境分层

先生成/选定清晰的人物母图，人物是背景主要内容，保持自然成年人体比例、完整头发和透明alpha。环境单独制作，按原主题延展；不要为了做宽屏，重新一次性生成整幅人物与环境，使脸、衣料和头发细节反复劣化。

人物层与环境层分别保存原图。补出的衔接区只处理环境或人物下边缘alpha，用平滑渐变融合，不能把人物整幅横向拉宽或给脸部加模糊以遮盖瑕疵。减少重复微纹理、锐化噪点和密集装饰，保留明确的形体与材质层次；低噪不是把人物磨平。

超分是可选、独立的人工步骤：已验证的批次使用waifu2x-ncnn-vulkan、cunet模型、2×、noise=-1（不额外降噪）。引擎/模型版本、输入输出尺寸、SHA256与处理参数应记录。一次RGBA推理曾输出错误alpha，该批次改用RGB超分、独立还原原alpha平面；须检查颜色和边缘，不能声称上游bug已修复。没有安装超分工具时，直接使用原层合成并明确尺寸来源。

## 4. 等比合成与终端布局

[Compose-Background.py](../scripts/Compose-Background.py)仅做离线合成：环境均匀缩放覆盖画布；人物用同一X/Y尺度摆在左侧，顶部留空间，下方alpha可淡出。右上文字区的阴影只影响环境，人物RGB不做额外模糊、磨皮或降噪。输入文件不改写，输出与元数据另存。非整数尺度会产生正常采样插值，不能承诺放大后每个输出像素都等于原像素。

先将人物和环境原层或已经人工超分的层放进工作目录，再运行：

```powershell
python scripts/Compose-Background.py --character work/character.png --environment work/environment.png --output work/terminal-4k.png --size 3840x2160 --character-height 2020 --left 246 --top 140 --bottom-fade 0.08 --darken-right 0.22
```

人物画布必须完全放进输出，越界会报错。调整高度与位置，不能用独立宽高拉伸来解决。默认4K仅表示合成画布3840×2160，脚本不会自动产生模型超分细节。

终端采用图片背景和主题配色；关注命令、输出、输入线的实际可读性。角色选项栏放在客户区安全位置，避开窗口标题栏、系统关闭与最大化按钮。气泡、聊天栏可以独立拖动摆放；保存位置后，角色切换/重新启动都应尊重用户设置。

## 5. 角色形状、毛绒材质与物理

气泡形状是各角色的原创UI设计，例如双云纹玉如意软枕。外轮廓、内容安全区、钱包区和按钮需要一起设计，不能只有一个异形背景，再把矩形交互框覆盖在上面。形状宽高、边距、SVG路径和主题颜色保存在角色配置中；必要时扩大气泡，保住字体、行距与按钮。

软绒材质用于视觉；大福一样的软糯是压缩、回弹、阻尼与碰撞的物理手感，两者不能互相替代。捏捏/拖动/放下/碰撞应有连续的弹簧响应，允许整个有效形体交互，透明区域应穿透，文字输入和按钮保留各自操作。原生渲染与网页/Three材质制作是不同端，不能用静态贴图验证代替运行时测试。

验收关闭按钮与各操作按钮的中心及四角是否在几何内，检查主体命中、透明穿透、拖动持久化、窗口移动跟随与常驻/聚焦模式切换。对低帧率、定时器和重复请求造成的卡顿先定位，不靠增大弹性掩盖。

## 6. 最终清单与人工签字

保留最终source→consumer映射、SHA256、版本号和修正链。错误早稿、账号配置、用户聊天记忆与旧角色备份不得随整套打包。来源、提示词与预览均采用相对路径；静态预览注明示例余额、示例终端文字和离屏渲染限制。

```powershell
python scripts/Validate-Assets.py --manifest examples/zhuangfangyi/assets-manifest.json --root . --report build/asset-checks.json
python -m unittest discover -s tests -p "test_*.py" -v
```

机器通过后仍要人工确认：身份与衣装、用户眼色修正、完整发型与头饰、自然比例、低噪细节、形状和UI布局、背景阅读性。截图只能证明其实际展示的状态；余额fixture不是账户查询结果，2D材质板不是实时GPU渲染证明。
